# v0.3 — NFS-mount: телефон как том в Finder (read-only MVP)

Date: 2026-08-25
Status: implemented; wire-verified with libnfs; kernel mount verified live

## Что работает (проверено на Nothing Phone A065)

- `pereprava mount [--path /Volumes/pereprava] [--port 34567]` — поднимает
  локальный NFSv3-сервер (fernfs, вендорен в `vendor/fernfs`) и монтирует
  том штатным `mount_nfs`. Права администратора — один GUI-промпт osascript
  (или запуск под root).
- Том виден в Finder: `/Volumes/pereprava/Внутренний общий накопитель/…`.
- Чтение каталогов — LOOKUP/READDIR поверх actor.hlist.
- **nfs-cat / libnfs**: чтение файла с телефона побайтово корректно.
- `--export "/1"` — экспортировать сразу первый сторадж (удобно для CLI-
  инструментов), по умолчанию "/" = список стораджей.
- `mount --serve-only --allow-unprivileged-source-port` — отладочный режим
  без прав root.

## Схема file-id (см. crates/nfs-mount/src/adapter.rs)

```
0x1                        корень устройства -> список стораджей
0x2+i                      корень стораджа i
1<<63 | idx<<48 | handle   реальный объект MTP
```

Read-only: write/create/remove/rename/setattr возвращают NFS3ERR_ROFS до
появления write-back staging (v0.4, как в оригинальном simple-mtpfs).

## Найденные и закрытые грабли

| Грабля | Решение |
|---|---|
| libnfs сначала пробует NFSv4 | отвечаем prog-mismatch, клиент откатывается на v3 (`?version=3`) |
| Ядро читает за EOF (rsize 128 KiB vs файл 21 B), Android отвечает ошибкой | клампим count к размеру объекта в адаптере |
| hard NFS + умерший USB = неубиваемый том | опция `soft,retry=1,retrans=2,timeo=50` в mount_nfs |
| ptpcamerad перехватывает устройство между операциями | kill-loop на время работы; `doctor` печатает рецепт |
| Незакрытая MTP-сессия клинит телефон | graceful close() из фазы 2 + resetUsbGadget как аварийный фикс |

## Как размонтировать застрявший том (если сервер убит жёстко)

```shell
sudo umount -f /Volumes/pereprava     # или diskutil unmount force
adb shell svc usb resetUsbGadget      # расколдовать телефон при необходимости
```
