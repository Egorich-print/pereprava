# v0.2 — Bundle-mode (.tar.zst single-object transfer)

Date: 2026-08-25
Status: implemented & measured (see docs/benchmarks/baseline.md)

## What shipped

- `pereprava pack <local-dir> [remote-parent]` — packs a tree into one
  deterministic `.tar.zst` and uploads it as a single MTP object.
- `pereprava unpack <remote.tar.zst> <dest>` — pulls the archive and
  extracts locally (byte-exact verified, incl. binary payloads).
- `pereprava bench --bundle` — runs the small-file phase twice
  (raw vs bundle) and prints the speedup factor.
- Refuses to overwrite existing archives; staging uses a transient temp
  file because MTP needs the final size upfront while zstd's output size
  is stream-unknown.

## Measured effect (Nothing Phone A065, USB 2.0)

500 × 8 KiB files: 21.95 s raw → 0.09 s bundled (**233×**).
Big-file path unchanged (~37 MiB/s = wire ceiling).

## Why not transparent per-file compression?

MTP carries raw object bytes; the phone owns its storage, so nothing can
compress "inside" the protocol without a companion agent on the device.
Bundle-mode attacks the actual bottleneck instead: per-object overhead.

## Deliberately deferred

- Phone-side auto-extraction (needs adb + static zstd on /data/local/tmp).
- ADB zstd transport lane (see benchmarks doc decision note).

Both stay listed in ADR-003 as future options gated on real need.
