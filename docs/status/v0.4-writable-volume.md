# v0.4 — Writable Finder volume

Date: 2026-08-26 (night build)
Status: implemented; E2E scripted (`scripts/e2e-write-test.sh`), device run
pending phone return to File-transfer mode (an OTA update knocked it off
the bus during the night).

## Что появилось

- **Том монтируется с правами на запись** по умолчанию
  (`--read-only` — явный откат). Finder позволяет создавать, редактировать,
  удалять файлы и папки.
- **Механика** (ADR-004): POSIX-записи оседают в локальный stage-файл;
  при закрытии файла ядро шлёт COMMIT → stage заливается на телефон как
  delete+upload одной парой операций актора. `flushed_dev` перепривязывает
  filehandle ядра к новому объекту, поэтому открытые дескрипторы живут.
- **Ядро (core)**: хэндл-базированные мутации HDelete/HUpload/HMkdir/HRename
  — адаптеру больше не нужно ходить путями; кэш инвалидируется на месте.
- **Классификация ошибок**: `Error::Disconnected` сохраняет класс из
  mtp-rs (is_disconnected/is_stale_handle); connect() делает 3 попытки с
  паузой против гонок ptpcamerad и пост-OTA «churn».
- **Фолбэк подключения**: connect_first перебирает ВСЕ USB-кандидаты и
  берёт первый, реально завершивший MTP-сессию. Поводом послужил USB-UART
  адаптер на шине, которому open_first отдавал телефонный слот и получал
  мусор вместо ответов.

## Ограничения v0.4

| Ограничение | Причина | Обход |
|---|---|---|
| Создание файлов внутри несозданной (unflushed) папки → EINVAL | каталоги не стадируются | сначала COMMIT родителя |
| Крэш между delete-old и upload-new теряет старую копию | атомарности в MTP нет | v0.5: upload-new-first + server rename |
| Один том = одна MTP-сессия | протокол | CLI-команды использовать при размонтированном томе |
