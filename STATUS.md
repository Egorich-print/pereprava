### Критичные исправления (v0.6, аудит)

- write-back: повторный COMMIT больше не плодит дубликаты на телефоне;
  удаление «сохранённого» файла реально удаляет его с устройства;
  `create` по существующему имени не срезает файл в ноль.
- `write` больше не врёт про `stable_how` → данные не теряются без COMMIT.
- индекс тома при flush берётся у родителя (SD-карта ≠ internal).
- staged read не отдаёт нулевой хвост; запись в каталог → `NFS3ERR_ISDIR`.
- `watch` не крэшлупит при занятом порту (порт = singleton) и
  перемонтирует том, если тот пропал; `test_session` ограничен таймаутом.
- actor: кандидаты без storages отвергаются; тикер прогресса не течёт;
  `force_close` снимает зависший актор.
- mount/unmount: корректное экранирование путей, один запрос пароля.
- `pull_tree`: защита от path traversal в именах с устройства.
- **Обрезанные передачи больше не выдаются за успех**: `download_into` сверяет
  фактические байты с заявленным объёмом, `upload_into` удаляет объект с
  устройства при несовпадении.
- **Зависший телефон больше не утекает USB-claim**: storage-probe жил в
  отдельной задаче, и по таймауту терялся только приёмник — задача продолжала
  держать устройство. Все последующие подключения падали с «device is held
  exclusively» до ручного сброса USB. Теперь probe прерывается.
- **`close()` больше не врёт об успехе**: результат teardown отбрасывался, и
  без дедлайна shutdown висел вечно. Теперь возвращает реальный результат,
  ограничен по времени, идемпотентен, прерывает актор по таймауту.
- **Удаление по хэндлу инвалидировало корень тома**, а не реальный
  родительский каталог: удалённый файл оставался виден в `ls` на время TTL
  кэша. Кэш запоминает, из какого каталога был получен каждый хэндл.
- **Пути валидируются до захвата устройства**: раньше опечатка давала «device
  is held exclusively», т.к. разбор пути происходил уже внутри актора.
- `bench` чистил телефон только при успехе — ошибка в любой фазе оставляла
  тестовый файл и каталог на устройстве.
- бандлы: `pack` шёл по симлинкам (затягивал постороннее поддерево, на
  предка уходил в бесконечный обход), `unpack` распаковывал прямо в
  назначение (любая ошибка оставляла каталог в неопределённом состоянии).
  Обе половины теперь согласованы, распаковка атомарна через staging.
- производительность тома в Finder: **3.73 → 11.9 MB/s (3.2×)** — убрана
  предшествующая `hinfo`-проверка перед каждым чтением, кэш атрибутов 2 с,
  `rsize`/`wsize` = 1 MiB. Это ~41% от прямого MTP-эталона (29.0 MB/s).

## v0.7 — глобальный аудит (4 субагента, все выводы проверены)

Проведено параллельное исследование `core` / `nfs-mount` / `cli` / `widget+repo`;
каждая находка перепроверялась по коду перед исправлением. Исправлено и
закоммичено (см. CHANGELOG), покрыто тестами, `clippy -D warnings` и CI зелёные:

- **Безопасность:** root-демон больше не исполняет бинарь из пользовательского
  checkout (`/usr/local/libexec`, root:wheel); status-файл и staging-каталог
  больше не уязвимы к symlink-атаке и читаемы только владельцем; `mount`
  отказывает `/` и относительным путям; `pull` валидирует имя файла с устройства.
- **Целостность данных:** `push --force` не удаляет файл на телефоне до
  открытия локального; staged-файлы видны в NFS LOOKUP; `remove` сначала
  удаляет объект на устройстве; переименование committed-файлов идёт через
  устройство; поколение filehandle больше не сталкивается в пределах секунды;
  read-only COMMIT возвращает ROFS.
- **Монтирование:** сохраняется фактический путь (`-N`), `unmount` работает с
  stale-томами, `--export` доходит до mount-источника, флаги привилегированных
  source-портов и режим в сообщении корректны.
- **Виджет:** добавлен Tauri capability (без него ACL был пуст и `invoke`/
  `listen` не авторизовались — UI мог выглядеть «статичным»); размонтирование
  не блокирует UI-поток; закрытие окна прячет окно; «Выход» работает; устаревший
  статус помечается, а не показывается как «смонтировано».
- **Производительность:** чтение через том больше не делает `hinfo` перед каждым
  128 КиБ-чанком — range-read идёт первым, метаданные только при коротком чтении
  или ошибке (2 → 1 round-trip на чанок в типичном случае).

**Не проверено на устройстве в этой сессии** (телефон не был подключён, sudo
недоступен): фактическая скорость чтения после оптимизации и e2e-прогоны.
Структурно round-trip на чанок сокращён вдвое; численное подтверждение —
в TODO. Перевод демона на новый root-бинарь: `scripts/daemon.sh update`.
