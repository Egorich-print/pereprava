### Критичные исправления (v0.6, аудит)

- write-back: повторный COMMIT больше не плодит дубликаты на телефоне;
  удаление «сохранённого» файла реально удаляет его с устройства;
  `create` по существующему имени не срезает файл в ноль.
- `write` больше не врёт про `stable_how` → данные не теряются без COMMIT.
- индекс тома при flush берётся у родителя (SD-карта ≠ internal).
- staged read не отдаёт нулевой хвост; запись в каталог → `NFS3ERR_ISDIR`.
- `watch` не крэшлупит при занятом порту (порт = singleton) и
  перемонтирует том, если тот пропал; `test_session` ограничен таймаутом.
- actor: кандидаты без storages отвергаются; тикер прогресса не течёт;
  `force_close` снимает зависший актор.
- mount/unmount: корректное экранирование путей, один запрос пароля.
- `pull_tree`: защита от path traversal в именах с устройства.

### Проверено на живом устройстве (Nothing A065, macOS 26.6)

- device-тест: полный roundtrip — ok.
- `scripts/e2e-write-test.sh`: запись 200 KiB через NFS → чтение → **byte-exact**,
  кросс-чек через CLI — ok.
- `scripts/e2e-overwrite-test.sh` (новый): 3 перезаписи одного пути → на
  устройстве ровно **1 объект**, содержимое = последняя запись.
- демон: авто-монтирование в `/Volumes/pereprava`, живые скорости в
  статус-файле, `SIGTERM` → корректный unmount, чистка stale-монтирований
  при старте, детект отключения (`state:"gone"`) и авто-reconnect без
  перемонтирования — всё подтверждено.
- виджет: появляется в меню-баре (после разрешения в macOS 26), читает статус.

### Известные ограничения

- macOS 26 (Tahoe): иконка в меню-баре требует разрешения
  `Системные настройки → Пункт меню → Разрешить в строке меню`.
- Чтение через том (~3.7 MB/s на 40 MiB) медленнее CLI-бенчей: адаптер
  делает `hinfo` перед каждым чтением. Кэш атрибутов — следующий шаг.
- `pack`/`unpack` в виджете не выведены; доступны через CLI.
